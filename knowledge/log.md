# Bundle Update Log

## 2026-09-05
* **Update**: Extended [the command surface](operating/cli-surface.md) with the four commands added after the pin — `learn`, `context`, `remind` and `issue` — listed in a section of their own rather than merged into the table above them, which is the parser's own output at `23db6d0` and must not be made to look as though it named them.
* **Update**: Corrected [the wake](collaboration/wake.md), which described three clocks nothing printed. `collab wake show` now prints `settle`, `min gap`, `timeout`, the retry pause with however much of it is left, when a delivery was last attempted and when one last arrived, and the reason `due()` gives at this moment; `collab status` carries the last two facts in two lines. Asking is read-only, which had to be arranged: the reminder's interval starts the first time the daemon asks whether one is due, so a command that asked while printing would have started a clock by being looked at. The same concept gains the reminder's route — recorded as `reminded_via`, written where the interval restarts — and `collab remind now`, which asks the daemon rather than delivering, so an agent holding both routes still gets exactly one.
* **Update**: Extended [the state directory](architecture/state-directory.md) with five paths that did not exist at the pin — the wake's durable state, the `remind now` marker, the reminder prompt, the status line's kept last line, and the diagnostic log — and with `learnings.md` in the SHARED `.collab/`, which is the one file here that deliberately does not belong to a session or to a per-agent home.
* **Update**: Extended [the trust model](operating/security-model.md) with the diagnostic log: off unless asked, events and never content, seven days, and the two places where keeping that rule costs something and it is paid anyway — an exception's type in place of its message, and a wake's exit code in place of its output.
* **Update**: Corrected [usage figures](collaboration/usage-figures.md), where `context_pct` had stopped being only a figure to look at: past `context_compact_at` the daemon compacts its own agent's context, which makes the owner stamp on `agent_stats.json` load-bearing in a second way — two agents in one checkout must not compact each other on the strength of a file one of them wrote.
* **Update**: Corrected [the envelope](architecture/envelope.md), where a `chat` body was described as always empty. A chat carrying `{learning: true}` is a fact meant to outlive the session, with its text prefixed `learning:` — the prefix for a receiver that has never heard of it, the body for one that has, because a message that merely looks like a learning is not a fact about anybody's repository. The hub is unchanged by it: the marker is sequenced, fanned out and stored like any other body, and nothing hub-side reads it.
* **Update**: Corrected [the state directory](architecture/state-directory.md), which described a `learnings.md` in the shared `.collab/` that is now the one file certainly not there. The store left the checkout: it lives beside the global config, grouped by a repository key derived from the normalised `origin` remote, so a learning belongs to the agent that found it and outlives any clone of the repository it is about. What the session directory holds now is the handover — one spool file per unpublished learning, drained by the daemon on a heartbeat and unlinked only once the publish succeeded, with the settled slug written back first so a retry republishes instead of making a second copy.
* **Update**: Corrected [activity](collaboration/activity.md), where `working` or `idle` and nothing else had stopped being true. A third state, `quiet`, is what the daemon decays its own agent's last word to after `activity_stale_after` minutes of no word AND no spend — both conditions, because a busy agent that forgot to update its status should be reminded rather than retired. It decays to `quiet` and never to `idle`: the first is a thing an agent says about itself and means free for work, the second is a thing the daemon observed and means nobody knows, and inferring one from the other hands work to an agent that is not there. Re-phrasing a stale line was not enough on its own, because the daemon re-asserts an unchanged activity every 300 s and so keeps a finished claim looking fresh all afternoon.
* **Update**: Corrected [the envelope](architecture/envelope.md) for the second marker on the same door. `{learning_sync: true}` asks the room for what it has; the request carries the asker's repository and the answering daemon does not read it, answering only from the bundle its own checkout entitles it to publish, and a receiver files what arrives under the key it derived for itself. A participant can ask, and cannot say which repository the answer is about or where it lands.
* **Update**: Extended [the wake](collaboration/wake.md) with what a stop does not stop. The wake is a command on disk rather than a running thing, so ending a session leaves it exactly where it was: silent while the session is down, and firing at whoever resumes it. Stops now name it, `--disarm` on both stop commands takes it with them, and `collab check` warns about a wake armed on a session with no listener while staying silent about one on a live session. A followed stream is the opposite shape and is named with its pid and never signalled, because it belongs to whatever armed it.
* **Update**: Corrected [the command surface](operating/cli-surface.md) again, where `learn` had been recorded as a positional and `--list`. It takes sub-verbs — `add`, `list`, `search`, `read`, `used`, `sync` — and neither it nor `issue` posts anything itself. Added `--disarm` on `kill` and `daemon stop`, and the fact that `host`, `join` and `check` now name the listening route for the tool they are talking to rather than listing both and leaving an agent to guess a fact about itself it does not reliably know.
* **Note**: The pin stays at `23db6d0`. Everything above is later than it, is said to be later than it in the prose, and carries no `verified` stamp; the bundle-wide re-pin is a separate act under the rule in [how to read this bundle](how-to-read-this-bundle.md). No new concept was created for the learnings feature for the same reason: a concept needs a `resource` pinned to the bundle's one revision, and there is nothing at that revision to cite. The viewer's roster foot changed in the same round and is recorded nowhere here, because the bundle has never described the viewer's layout: there was no true statement to correct, and inventing a concept for it would pin a claim to a revision that does not hold it.
